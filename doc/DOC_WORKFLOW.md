## 2. 目录结构与用途

```
doc/
├── README.md                    文档导航（读文档永远从这里进）
├── DOC_WORKFLOW.md              本文件：规范与更新机制
├── BUILD.md                     环境安装与编译（从零配置）
├── keship_architecture.md       系统架构：目录树、模块设计、数据流 + 专题笔记索引
├── keship_developer_guide.md    开发指南：技术栈、编译运行、文档索引
├── keship_issues_log.md         问题日志：Bug、根因、修复过程（按时间轴追加）
├── keship_plans.md              方案索引（doc/plans/ 的唯一入口）
├── plans/                       方案 / 计划 / 设计（含未完成与已实施）
├── notes/                       活跃专题笔记
│   └── archive/                 已过时 / 已被取代的笔记（只读参考）
└── subagent_routing.md          工具环境配置（与项目本体无关）
```

| 目录 | 放什么 | 不放什么 |
|------|--------|----------|
| `doc/` 根 | 长期有效的全局文档 | 一次性记录 |
| `notes/` | 已落地的设计、理论、修复复盘 | 未实施的设想 |
| `notes/archive/` | 已被后续重构取代的内容 | —— |
| `plans/` | 方案、计划、设计方案 | 已收敛为事实的结论（应转 notes/） |

## 3. 强制更新触发表（核心）

**改了代码就要改文档。** 下表中任一行为发生后，必须在**同一次工作内**完成右侧更新：

| 你做了什么 | 必须同步更新 | 不更新的后果 |
|-----------|-------------|-------------|
| 新增 / 删除 / 移动 `src_cpp`、`include` 下源文件 | `keship_architecture.md` 的文件组织架构树 | 目录树失真，按图索骥找不到文件 |
| 新增 / 改 GUI 对话框、编辑器、Viewer | `keship_architecture.md` 的 GUI 层小节 | 功能无据可查 |
| 修复 Bug / 定位到根因 | `keship_issues_log.md` 的开发时间轴追加一行；重大者另写专题笔记 | 同类问题反复排查（本项目已发生过） |
| 新增物理 / 算法 / 数据结构设计 | 新建 `notes/*.md` + 在架构文档专题表登记一行 | 体检项 1 报「未登记」 |
| 推翻 / 取代了某笔记的做法 | 原笔记移入 `notes/archive/`，头部留一行指向新文档 | 后人按旧方案实现，返工 |
| 新增方案 / 计划 | 落 `doc/plans/` + 在 `keship_plans.md` 登记一行 | 体检项 3 报「未登记」 |
| 改动 ksw / ksm / kswf 文件格式 | 架构文档对应章节 + 显式版本号 | 旧档无法读取，且无版本号可判别 |
| 改动外部约定（topic 命名、文件路径、坐标系、单位） | 架构文档 + 相关笔记 | 联调阶段才暴露，排查成本高 |
| 给出 / 反转一项关键技术决策 | 架构文档「关键技术决策」+ 决策日期与理由 | 后来者重复争论同一问题 |

## 4. 命名规范

| 类型 | 命名 | 示例 |
|------|------|------|
| 专题笔记 | `<主题>.md`，一次性记录加日期后缀 | `fossen_physics_refactor.md`、`dynamics_audit_2026-08-14.md` |
| 方案 | `YYYYMMDD_<主题>_plan.md` 或 `<主题>_plan.md` | `20260818_structure_tree_refactor_plan.md` |
| 归档 | 保持原名，不放前缀 | `notes/archive/ui_refinement_session2.md` |

规则：不加空格、不写"新建/副本/最终版"，版本靠 git 而非文件名。

## 5. 归档规则

出现任一条即归档：

1. 文中描述的组件已被删除或重写；
2. 文档指向的实现已被后续笔记明确取代；
3. 内容属于某次排查的中间过程，结论已吸收到别处。

归档动作三步：**移动文件 → 在文件头部加一行"已被 XXX 取代" → 更新所有指向它的链接**（含跨目录）。

> 第 3 步最容易漏，也正是本次整理唯一残留的断链来源。归档后务必跑体检脚本。


## 8. 体检脚本与它的可信边界

```bash
cd ~/keship_ws && python3 tools/check_docs.py
```

覆盖 5 项：架构文档笔记覆盖度、内部链接有效性、方案索引覆盖度、重复副本检测、笔记规范。

### 使用时的三条铁律

1. **样本数为 0 一律算「未能判定」，不算通过。** 脚本对此输出 `[??]` 而非 `[OK]`——看不到样本的检查等于没检查。
2. **「通过」与「未判定」分开展示**，不允许合并为一句"没有问题"。
3. **改脚本后必须做回归测试**：先注入一个已知错误（例如在某笔记里写一条指向不存在文件的链接），确认脚本能抓到，再还原重跑确认恢复。

> 提示：本次启用时已做过一次回归——体检首跑把代码块中的 C++ lambda `const gz::msgs::Pose_V &_msg` 误判为链接，
> 修掉解析器（剔除代码块与行内代码后再匹配）后链接样本数从 77 降为 76，误报消失。
